# Ecosystem examples

These examples illustrate terminology. They do not establish current version
numbers, platform availability, release frequency or support end dates.
Check the linked policy for live decisions. Reviewed on 2026-11-11.

| Project | Example labels | What the example shows | Primary source |
| --- | --- | --- | --- |
| Chrome | Canary, Dev, Beta, Stable | A product's channels can form a promotion path | [Channels](https://developer.chrome.com/docs/web-platform/chrome-release-channels) |
| Rust | Nightly, Beta, Stable | Build cadence and a release train coexist | [Rust Book](https://doc.rust-lang.org/book/appendix-07-nightly-rust.html) |
| Debian | Unstable, Testing, Stable, Oldstable | Distribution labels have specific meanings | [Releases](https://www.debian.org/releases/) |
| .NET | LTS, STS | Support length is distinct from release quality | [Support policy](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core) |
| Firefox | Nightly, Beta | Prerelease channel naming is product-specific | [Channels](https://www.mozilla.org/en-US/firefox/channel/desktop/) |
| Ubuntu | LTS, Interim | Stable releases can have different maintenance windows | [Release cycle](https://ubuntu.com/about/release-cycle) |
| Kubernetes | Alpha, Beta, GA | Labels can apply to features rather than entire products | [Feature gates](https://kubernetes.io/docs/reference/command-line-tools-reference/feature-gates/) |
| npm | latest, next | Distribution tags are mutable pointers | [Dist-tags](https://docs.npmjs.com/adding-dist-tags-to-packages/) |

Do not copy one project's support duration or promotion criteria into another.
